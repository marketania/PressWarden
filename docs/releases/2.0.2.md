# PressWarden 2.0.2

Readable security investigations, a simpler command guide and stronger handling
of incomplete scanner coverage.

## Everyday use

- Use `scan SITE` for a routine security audit. Choose one focused mode with
  `--full` / `--deep`, `--incident`, `-db`, `-php`, `-js` or `--runtime`.
- Use grouped help, task-specific help and `help all` to find the right action.
  `status` is the shorter spelling for saved run status; existing commands remain
  supported.
- Control terminal presentation with `--color=auto|always|never`, `--no-color`
  or `NO_COLOR`. Redirected output stays plain by default.
- Follow the rewritten README from selected-source installation through
  configuration, site discovery, a first inspection, saved results and recovery.

## Correctness and coverage

- Reject malformed targets, unusable or unsuccessful saved configuration, and
  failed explicit overrides before dispatch. Preserve multiline exclusions and
  reject invalid roots without widening scope.
- Keep color flags from consuming a missing target, provide useful empty
  history/status output, and reject invalid or unrecorded run IDs.
- Report missing local prerequisites for configured optional scanners without
  invoking their APIs during `doctor`.
- Retain partial YARA findings and report incomplete WPScan, plugin checksum and
  static-core coverage. An unavailable check cannot establish a clean result.
- Preserve findings and evidence when reporting fails, sanitize terminal display
  text, and retain exact evidence bytes through excluded-site projection.
- Include required helper files in installation and update validation while
  retaining valid older self-contained source archive compatibility.

## Update an existing installation

From the installed PressWarden directory:

```bash
./presswarden update
./presswarden version
./presswarden config-new
```

The default updater follows `main` and refreshes enabled intelligence feeds.
Confirm version `2.0.2` or newer. A saved ref or archive override can pin an older
source; choose a newer trusted source deliberately when using one. Git development
checkouts use Git instead of the self-updater. Private configuration, reports and
evidence are preserved; no data migration is required.

The source-release workflow verifies all required checks on the exact merged main
commit before publishing its archive, checksums and `SOURCE.json` provenance.
Production-specific provider availability and scanner coverage still depend on
the configured environment. Ordinary scans retain website mutation safeguards;
recovery actions remain explicit and interactive.
