# PressWarden 2.0.3

Remediation prompts during scans and a manual cleanup command for old
quarantine cases.

## Everyday use

- In a terminal, a scan now asks `Remediate now? [y/N]` right after each
  remediable section that has findings, for example the `.env` search and then
  the public log search. Findings are printed and saved first. The default is
  No. Yes quarantines a verified private copy before removal, and protected
  paths stay excluded. Without a terminal, or with `PRESSWARDEN_INTERACTIVE=0`,
  scans only print the `remediate files` command.
- `remediate files` now includes the public exposure check: `.env` and
  credential files, keys, database/config backup artifacts, VCS metadata and
  public logs. These are quarantined, not plainly deleted.
- `quarantine prune --older-than=DAYS [--apply]` removes old quarantine cases.
  It previews by default. Only complete, hash-verified cases are eligible. Apply
  needs a typed confirmation, must match the previewed set exactly, renames
  before removal and writes a private prune log.

## Update

From an installed PressWarden directory, run:

```bash
./presswarden update
./presswarden version
./presswarden config-new
```

Confirm version `2.0.3` or newer. Private configuration, reports, evidence and
quarantine are preserved. There are no data migrations or new sibling
dependencies. Source publication does not run scans or remediation against any
website.
